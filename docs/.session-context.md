## Decisions & Context

### Persistent Shell Pattern
- Navigation is layout-level via `SiteShell.jsx` in `BaseLayout.astro` with `transition:persist="site-shell"`
- State management uses React local state + custom DOM events (no global store)
- GSAP handles all drawer/overlay animations via `useGSAP`
- `transition:animate="none"` + `::view-transition-old/new(site-shell)` CSS suppresses Astro's default page-swap fade
- `scrollbar-gutter: stable` on `html` prevents layout shift from scrollbar presence

### CSS Architecture for Nav
- Nav bar height is `2.929rem` (41px at 14px base) — hardcoded in rem, NOT a CSS variable (the `--nav-height` variable approach caused regressions)
- `translateY(-100%)` is the CSS fallback for closed state; GSAP measures actual panel height and sets precise `y` offset on mount
- The shell uses `position: fixed; top: 0` with `pointer-events: none` (re-enabled on interactive children)

### Known Fragility
- The info-wrapper initial position depends on GSAP measuring `.info-panel` height after mount — any CSS that changes visibility/display before GSAP runs can break the initial state
- Sub-pixel gap between nav and content below is a known cosmetic issue; DO NOT attempt to fix with overflow/visibility changes on `.site-shell` or `.info-wrapper`
