  (2) Globe video = **480p** desktop default. (3) Scroll-lag = **dials + stagger now,

  live videos, more staggered fan-out** (invert the earlier "fewer live" rec →
  `WORLD_MAX_LIVE` 3→4; pay for it with the tile cut + parallel-fill).
- **Globe frame-drop root cause (refined):** NOT the VideoTexture uploads — three r184
  gates those to `requestVideoFrameCallback` (a modest constant). It's an **uncapped
  promote burst**: a drag synchronizes demote-crossfades then refills up to 7 slots →
  ~7 `new Hls()` on one frame. Fix = promote cap + drag-defer.
- **480p mechanism:** desktop is capped TWICE (270p manifest + `preferMinQuality`
  level-0 lock). Must pin `min==max=480p` so level-0 lands ON 480p — bumping
  `max_resolution` alone would keep picking the lowest sub-480p rung. Filtering is
  correct as-is (don't touch). Mobile (540p) already right.
- **Deck overlap mechanism:** band placeholder is appended to the phyllotaxis seq then
  DISCARDED while the deck is force-placed top-right (`BAND_POS_X/Y`) → unreserved
  footprint → tiles land under it. Fix = rectangular exclude-zone in `placeTiles` keyed
  to the LIVE `BAND_POS_X/Y` (tracks `?bandx/?bandy`), + drop the phantom placeholder.
- **Bundle facts:** zero code-splitting in `src/`; `hls.js` (~130KB gz) + all 4 dev
  benches ship statically on `/` and `/work`. `styled-components`/`@mux/mux-node` are
  Studio-only (not in target bundles) — confirmed non-issues. Dev routes are separate
  chunks — 0 KB on `/`+`/work`.
- **Shell over-density (minor):** `SHELL_MERIDIANS/PARALLELS` 250/230 is a single
  LineSegments (1 draw call), over-built ~4-8×, but a mount cost NOT the Turn spike —
  optional trim, design call.
